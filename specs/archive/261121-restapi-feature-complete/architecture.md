## 1. Architecture overview

```
 clients (afs CLI, @afs/sdk, console, pipelines, security tooling, workloads)
        │ HTTPS /v1 (OIDC | afsk_ key | projected SA token aud afs-api)
        ▼
 afs-api ── httpapi (middleware: request id → contract version → CORS → rate limit → authn → route authz
        │            (401/404/403 rule) → suspended-team guard → idempotency → handler)
        │   usecase/<area> ── domain ── authz
        │   adapter/postgres (afs_app, SET LOCAL session) ─────────────┐
        │   adapter/aws/secretsmanager (only AWS client in afs-api)     │
        ▼                                                               ▼
                                                         RDS PostgreSQL 17 (-db schema 000014)
 afs-reconciler (leader) ── engine (LISTEN afs_desired_state, 30 s poll, 10 min resync, work queue)
        │   usecase/reconcile/<controller> ── ports ── adapter/k8s (SSA, envtest) , adapter/aws/* (fakes in tests)
        │   collectors (activity, traffic), housekeeping (outbox → EventBridge, partitions, purge, org mirror)
 afs-gateway ── gatewayhttp (Bedrock + Anthropic wire) ── usecase/gateway (identity, reserve, settle, thresholds, tags)
        │   adapter/k8s/podcache + tokenreview ; adapter/postgres (afs_gateway) ; adapter/aws/bedrock (assume team role)
 afs-billing ── usecase/billing (CUR, reconcile, price sync, showback, schedules, cost tags) ── athena/pricing/ce/s3
```

Dependency rule (AGENTS.md): `cmd/*` → `adapter/*` → `usecase` → `domain`; `authz` is imported by
`usecase` and `httpapi`. `domain` and `usecase` import only the standard library, `authz` and each other. A
test (`internal/archtest`) parses imports with `go/packages` and fails on a violation; it also fails if
`cmd/afs-api` constructs any AWS service client other than Secrets Manager (RA-US-5.4), any Kubernetes
client (RA-US-2b.4), or any S3 client (RA-US-14.5).

## 3. Collision-free parallel work

Parallel streams in worktrees touch disjoint files. The few shared files are handled like this:

| Shared item | Rule |
|---|---|
| Route table | Generated once from `api/contract/operations.json` in M0 (`routes_gen.go`): every operation is registered with its method, path, permission and scope and a `501 NotImplemented`-style `InternalError` placeholder. A stream binds real handlers in its own `h_<area>.go` by returning `map[operationId]Handler` from `(*Server).<area>Handlers()`; `handlers.go` already lists every area registrar (created empty in M0-D). No stream edits `routes_gen.go` or `handlers.go` |
| OpenAPI | Fragments per contract section; the bundle is regenerated, never hand-merged. After M0 a stream that must change an operation's shape edits only that section's fragment and reruns `make openapi` |
| `go.mod`/`go.sum` | Streams may add requirements. On merge, conflicts are resolved by taking both and running `go mod tidy`; the milestone exit task does the final tidy |
| `cmd/*/main.go` | Created with a `wire(cfg, deps) []component` list that calls `wire_<area>.go` functions; each stream adds its own `wire_<area>.go` and one line to the list in `main.go` (a trivial merge) |
| `internal/domain` | Shared primitives are created in M0-S; aggregates are one file each, owned by one stream |
| Fakes | Cross-cutting fakes in `port/fakes` (M0-F); area fakes in `<area>/<area>test` |
| Helm values | `values.yaml` keys per component in separate files `values/<component>.yaml` merged by the chart's `_helpers.tpl`; templates one file per object |
| `status.md`, `tasks.md` | Only the milestone agent (not workers) updates them, after merging each stream |

Integration order within a milestone: streams merge into the milestone branch (the feature branch) in the
order listed in tasks.md; each merge reruns `make gate`.

## 4. Layer responsibilities

| Layer | Does | Does not |
|---|---|---|
| `domain` | Entities, invariants, value objects, domain errors, event types, tag and budget math, report range selection | I/O, time (takes `now`), ids (takes them) |
| `authz` | The permission catalog, roles, `Authorize`, `Effective`, `CanGrant` | Read the database (the caller passes the resource attributes) |
| `usecase/<area>` | One exported function or method per operation; opens the transaction, loads, checks domain rules, writes row + audit + outbox, returns domain results | HTTP, SQL, AWS |
| `usecase/reconcile/*` | Compute desired cluster/AWS state from rows, call ports idempotently, write status and conditions, emit events, drive finalizer steps | Know Kubernetes or AWS types |
| `usecase/gateway` | Identify caller (through ports), check model and team state, reservation math, settle rules, threshold decisions, metadata | Know Bedrock wire formats |
| `usecase/billing/*` | Jobs with injected clock | Know Athena SQL dialect details (adapter) |
| `adapter/httpapi` | Decode, validate shape, map DTO ↔ domain, call one use case, encode; middleware; error mapping | Business rules |
| `adapter/postgres` | SQL, session settings, SQLSTATE → domain errors (database contract §6), retries | Decide access |
| `adapter/k8s` | Render and server-side apply, watches, envtest helpers, pod cache, TokenReview | Decide what should exist |
| `adapter/aws/*` | SDK calls, pagination, error mapping, tagging | Decide what should exist |
| `adapter/gatewayhttp` | Bedrock and Anthropic wire, event stream and SSE framing, header stripping | Spend rules |

## 5. Data flow

1. **Mutation** (`afs-api`): request → middleware (§1) → use case → `TxRunner.InTx(session)` → repository
   write (`version` check) → `AuditWriter` → `OutboxWriter` → idempotency completion → commit → response
   with `status.phase = Pending` (from `resource_status` when present) and `ETag`.
2. **Change feed**: the `-db` trigger sends `pg_notify('afs_desired_state', '<table>:<team_id>:<id>')` →
   reconciler engine maps table → controller → work queue key `(kind, id)` → controller reconcile →
   ports → status write (`observed_generation = generation`) → `*.status_changed` event when phase changes.
3. **Outbox**: housekeeping publisher reads unpublished `outbox_events` in id order per aggregate →
   EventBridge `PutEvents` (source `afs`, detail-type = type) → `published_at`; failures bump `attempts`
   with exponential backoff (1 s → 5 min).
4. **Model call**: agent → `afs-gateway` (TLS) → identify by source IP (pod cache + Cilium identity) →
   optional token TokenReview → team state and model → `ensure_spend_counter` → `reserve_spend_held` →
   assume `afs-<team>-bedrock` → Bedrock (team profile, `requestMetadata`) → `settle_reservation` →
   batched `usage_events` → threshold events via outbox.
5. **Billing**: daily Athena CUR query → `cost_daily` (tag sets from CUR line item tags) →
   `cost_reconciliations` → `cost.variance_detected`; Price List → proposals; schedules → CSV → S3 →
   `report.delivered`.

## 6. Sequence: create a team (RA-US-3)

```
client → afs-api POST /v1/teams (Idempotency-Key)
  idempotency.Begin(principal,key,op,sha) ──► 23505? → replay | 409
  authz: teams:create (svc) → allowed
  teams.Create: domain.NewTeam → tx: insert teams, team_models, team_tags, budgets (ephemeral), role_bindings(first admin)
                audit(team.create) + outbox(team.created) + idempotency.Complete(201, body)
  deferred required-tag trigger at commit → 23514 → ValidationError details.missingTags
← 201 Team {status.phase: Pending}, ETag "1"
reconciler: NOTIFY teams:<id>:<id> → team controller → namespace, policies, IAM, profiles → resource_status Ready
```

## 8. Architectural decisions (recorded as ADRs in `docs/architectural-decision-record.md` during M0–M1)

| # | Decision | Alternatives | Why |
|---|---|---|---|
| A-1 | ADR-002 accepted: `net/http` ServeMux, our route table | chi, echo | Route table generated from the contract |
| A-2 | OpenAPI from contract extract + hand-written fragments + bundler + equality tests (research §3.1) | Generate OpenAPI from Go code; hand-edit one file | Contract is markdown; fragments avoid collisions; equality tests catch drift |
| A-3 | Generated route table with placeholders for all 182 operations in M0 | Add routes as built | Route-permission test green from day one; no route table merges |
| A-4 | Reconciler controllers in `usecase/reconcile`, Kubernetes rendering in `adapter/k8s/render` | controller-runtime reconcilers holding logic | Keeps Kubernetes out of use cases (AGENTS.md) and lets use cases run with fakes |
| A-5 | Third-party CRDs as unstructured | Import Cilium, Karpenter, ESO Go modules | Dependency weight and version pinning |
| A-6 | One work queue keyed by `(kind, id)` with per-kind workers; team-level ordering for delete | Separate controllers per process | One leader, simple ordering |
| A-7 | `afs-api` uses RDS IAM auth token signing (`feature/rds/auth`, a local signature, not a service client) | Static password | No long-lived credentials; allowed by the RA-US-5.4 test's allowlist |
| A-8 | Gateway caches team, model, price, budget and tag data, invalidated by `LISTEN afs_desired_state` and a 60 s TTL | Query per call | < 25 ms p99 |
| A-9 | Usage rows batched (≤ 1 s, ≤ 500 rows) through `COPY` | Insert per call | Gateway contract §8 |
| A-10 | e2e, load, conformance and restore suites are build-tagged and compile in CI | Skip them | They need a cluster; compiling keeps them honest |
